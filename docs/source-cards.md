# 新景點：先做平面圖文整理，再進 3D

新景點不直接建模。先把 `G:\Ai Data\今昔` 的素材整理成「史料卡」，證據足夠的才進 3D。這樣能避免臺中 1935 版那種建錯（見 `docs/scene-inventory.md` 第 1 節），地圖上也能先有內容（圖鑑頁）。

## 1. 流程

1. **選景點**：從 `public/data/scene-registry.json` 的候選（`status: planned`）挑一處，或新增一筆。
2. **整理史料卡**：每張照片／地圖／文字一張卡，填下方欄位。存在 `docs/sources/<景點 id>/cards.json`（只存文字與縮圖路徑；授權未確認的原圖不進 repo）。
3. **圖鑑頁上線**：卡片數 ≥ 3、有座標後，registry 狀態改 `dev`，地圖與圖鑑先顯示文字與可公開的圖。
4. **進 3D 的門檻**（全部達成才建模）：
   - 主建物至少一張**正面**照片，且至少一張**側面或斜側**照片；
   - 年代確定到 ±5 年；
   - 至少一個尺寸依據（實測圖、官方文字，或照片中可量的參考物）；
   - 座標與正面朝向已用 OSM 或古地圖核對；
   - 至少一張可公開（PDM／CC）的對照照片，供驗收並排比對。
5. **建模與驗收**：依 `docs/art-direction.md` 第 7 節驗收表。

## 2. 史料卡欄位

| 欄位 | 說明 | 例 |
|---|---|---|
| `id` | 景點 id＋流水號 | `hsinchu-station-003` |
| `file` | 素材在 G 槽的相對路徑 | `新竹/新竹驛/1930明信片.jpg` |
| `kind` | photo／postcard／map／aerial／drawing／text | `postcard` |
| `subject` | 拍到什麼（建物、街道、橋…） | `新竹驛正面與站前廣場` |
| `year` | 年代；不確定寫範圍 | `1930–1935` |
| `yearBasis` | 年代依據 | `郵戳 1933`、`館藏標示`、`推估：站前有 1931 年設的路燈` |
| `place` | 拍攝位置（街道或座標） | `站前廣場南側，中正路口` |
| `direction` | 拍攝方位（相機朝向）＋看到的立面 | `朝東北，正面＋左側立面` |
| `dimensions` | 可量的尺寸證據 | `入口拱高約 4 人高（≈6.5 m）`、`立面 7 開間` |
| `features` | 建模要用的特徵清單 | `中央鐘塔、山牆、兩側翼棟、銅板屋頂` |
| `confidence` | A 直接佐證／B 可推估／C 只能示意 | `A` |
| `license` | 授權與來源 | `PDM，國家文化記憶庫 id=…`、`未確認（僅參考）` |
| `publishable` | 能否放上網站 | `true`／`false` |
| `notes` | 衝突、疑點 | `檔名寫 1927，但站房 1936 才完工` |

## 3. 等使用者電腦開機後要做的事

`G:\Ai Data\今昔` 只能從使用者電腦讀取（只讀不改）。建議順序：

1. **臺中**（`臺中` 資料夾）：找臺中驛側面、背面與 1930 年代屋頂照片，確認塔的形狀，作為處理臺中 1935 版的依據。
2. **新竹**（`新竹`）：registry 已列為下一個場景候選，座標仍是 null。
3. **嘉義、基隆、花蓮、台東**：registry 候選，先做卡片與圖鑑。
4. `全台車站` 的 22 支 MP4 尚未辨識站名，可一併標註。
